The provider learns "paid by a valid, unspent credit" — never who.

The problem

  • AI agents now pay per API call (x402 micropayments, API keys tied to wallets).
  • Every paid call is linkable: which agent, which endpoint, how often, when.
  • For an agent, that log is its strategy: trading signals, research targets, customers.
  • Today the only options are: trust the provider, or don't use paid APIs.

The idea

  • Buy once: the agent buys a bundle of N calls; the agent sends only ownerTag = H(secret); the circuit stores the commitment H(ownerTag, N). Self-serve buy() pays NIGHT into the contract.
  • Spend anonymously: each call = one ZK redeem() proving "I own an unspent use of some bundle in the tree".
  • No double spend: a per-use nullifier H(secret, i) goes into a public set.
  • Bound to the request: sha256(nonce ‖ claim) is recorded next to the nullifier → only the paying agent can collect the response (no front-running).

What the circuit enforces

  • ✔ path leaf = bundleCommitment(bundle) → N cannot be inflated
  • ✔ root is a current or past root of the tree → only paid bundles
  • ✔ useIndex < N → exactly N spends
  • ✔ nullifier unspent → no replay / double spend
  • ✔ commitment built in-circuit from (ownerTag, N) → no inflation via issue() or buy()
  • ✔ only the operator can issue() / withdraw(); buy() must pay N × price NIGHT

21 tests (16 contract + 5 HTTP paywall) cover every rule plus unlinkability, front-running, request binding and concurrent replays — all passing.

How it compares

  • No custodian: remaining credits are enforced in the circuit (i < uses + one nullifier per credit), not reported by a backend
  • No per-call settlement: the provider only reads the ledger in its HTTP 402 gate
  • Can't mint extra credits: the bundle commitment is computed inside the circuit
  • Front-running safe: each spend is bound to sha256(nonce ‖ claim)
  • Related Midnight projects: Shade 402 (private x402 pool payments), Avtar.ai (voucher channels), Sigil (private agent policies). Details in the README.

Market & adoption

  • Who pays: API providers selling to agents (data, search, on-chain analytics) who want privacy-conscious agent customers.
  • Why now: agent-to-API payments (x402) are growing; privacy is the missing piece.
  • Adoption path: drop-in X-Punchcard header next to x402; we run our own paid agent API and will accept Punchcard first.
  • Model: providers keep 100% of the bundle price; optional hosted verifier.
  • Pilot (ours, live): Nightshift x402 API — 21 paid endpoints at $0.003 per call, listed on x402scan. Plan: also sell 100- and 1,000-call Punchcard bundles at the same per-call price.
  • Why a bundle, not per-call x402: one purchase instead of N public payments; each call costs a redeem fee in DUST, not a USDC transfer.

Roadmap & honest limits

  • Next: Lace wallet in the UI so agents can redeem against the live preview contract from the page (read-only live view already shipped).
  • Shielded payment inside the purchase, so buying is private too.
  • Package the gate (verified against the preview indexer) as drop-in middleware next to x402.
  • Bundle expiry, per-endpoint credit classes.
  • Limits: purchase is public, unlinkability starts after it; anonymity set = bundles before the proven root; use a fresh fee wallet + hidden IP for redemptions.
